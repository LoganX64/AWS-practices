# Infrastructure as Code

## 1. What is Infrastructure as Code?

Normally, we can create an AWS resource manually:

```
AWS Console
   ↓
Create S3 bucket
   ↓
Configure settings
   ↓
Create bucket
```

Or using AWS CLI:

```
aws s3 mb s3://my-bucket
```

Terraform lets us describe the infrastructure in a file:

```
main.tf
   ↓
Terraform
   ↓
Floci / AWS
   ↓
S3 bucket
```

The important difference is that the infrastructure configuration becomes code that can be saved, reviewed, modified, and reused.

## 2. First Terraform project

Create a new folder:

```
cd D:\practise\AWS-practices
mkdir 03-terraform-basics
cd 03-terraform-basics
mkdir 01-iac
cd 01-iac
```

Create: `main.tf`

Put this in main.tf:

```
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
    }
  }
}

provider "aws" {
  region                      = "us-east-1"
  access_key                  = "test"
  secret_key                  = "test"
  skip_credentials_validation = true
  skip_requesting_account_id  = true
  skip_metadata_api_check     = true

  endpoints {
    s3 = "http://localhost:4566"
  }
}

resource "aws_s3_bucket" "lab" {
  bucket = "terraform-iac-lab"
}
```

Save the file.

## 3. Understand the important parts

Don't worry about every line yet.

Terraform block

```
terraform {
  required_providers {
    aws = {
      source = "hashicorp/aws"
    }
  }
}
```

This tells Terraform:

`I need the AWS provider.`

### Provider

```
provider "aws" {
```

The provider is what allows Terraform to communicate with AWS-compatible APIs.
In our case:

```
Terraform
    ↓
AWS provider
    ↓
Floci
    ↓
S3
```

### Resource

```
resource "aws_s3_bucket" "lab" {
  bucket = "terraform-iac-lab"
}
```

This means:

```
resource type = aws_s3_bucket
resource name = lab
bucket name  = terraform-iac-lab
```

The Terraform resource address is:

```
aws_s3_bucket.lab
```

This distinction is important.

```
resource "aws_s3_bucket" "lab"
```

`aws_s3_bucket` is the resource type.

`lab` is the Terraform resource name.

## 4. Initialize Terraform

Run:

```
terraform init
```

we should see Terraform initialize the AWS provider.

check:

```
Get-ChildItem
```

we should now have something similar to:

```
main.tf
.terraform\
.terraform.lock.hcl
```

Do not manually edit .terraform.

## 5. Format the configuration

Run:

```
terraform fmt
```

Terraform formats your .tf files.

## 6. Validate

Run:

```
terraform validate
```

Expected:

```
Success! The configuration is valid.
```

This checks the Terraform configuration itself.
It does not create the bucket.

## 7. See what Terraform wants to do

Run:

```
terraform plan
```

we should see something indicating that Terraform wants to create:

```
aws_s3_bucket.lab
```

Look for:

```
Plan: 1 to add, 0 to change, 0 to destroy.
```

At this point:

```
Bucket does NOT exist yet.

terraform plan
       ↓
"What would happen?"
```

## 8. Apply

Now run:

```
terraform apply
```

Terraform will show the plan and ask:

```
Enter a value:
```

Enter:

```
yes
```

we should eventually see:

```
Apply complete! Resources: 1 added, 0 changed, 0 destroyed.
```

9. Verify with AWS CLI

Because we're using AWS cli:

```
aws s3 ls
```

we should see:

```
terraform-iac-lab
```

we can also directly inspect it:

```
aws s3api head-bucket --bucket terraform-iac-lab
```

If successful, there should be no error output.
Now we have created the same type of resource using two different approaches.

### AWS CLI

```
aws s3 mb s3://some-bucket
```

Terraform

```
resource "aws_s3_bucket" "lab" {
  bucket = "terraform-iac-lab"
}
```

## 10. Terraform state

After terraform apply, check:

```
Get-ChildItem
```

we should see:

```
main.tf
terraform.tfstate
.terraform\
.terraform.lock.hcl
```

Terraform created:

```
terraform.tfstate
```

This is important.
Terraform uses state to keep track of resources it manages.

we can inspect it:

```
terraform show
```

we should see information about:

```
aws_s3_bucket.lab
```

we can also check the resource address:

```
terraform state list
```

Expected:

```
aws_s3_bucket.lab
```

So we now have:

```
main.tf
   ↓
desired configuration

terraform.tfstate
   ↓
Terraform's record of managed infrastructure

Floci
   ↓
actual S3 bucket
```

Don't modify terraform.tfstate manually.

## 11. Change the configuration

Change:

```
bucket = "terraform-iac-lab"
```

to:

```
bucket = "terraform-iac-lab-2"
```

Save the file.

Now run:

```
terraform plan
```

Terraform should detect that the existing resource needs to change/recreate because the bucket name is part of its identity.
Do not apply yet.

This is one of the fundamental Terraform workflows:

```
Change code
    ↓
terraform plan
    ↓
Inspect proposed changes
    ↓
terraform apply
```

For this exercise, after inspecting the plan, run:

```
terraform apply
```

Enter:

```
yes
```

Then verify:

```
aws s3 ls
```

## 12. Destroy it

When finished:

```
terraform destroy
```

Enter:

```
yes
```

Then verify:

```
aws s3 ls
```

The Terraform-created bucket should be gone.
