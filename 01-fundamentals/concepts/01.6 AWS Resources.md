# AWS Resources

## What is an AWS Resource?

An AWS resource is an individual thing we create or use inside an AWS service.eg:

- EC2 → an EC2 instance
- S3 → an S3 bucket
- RDS → an RDS database instance
- VPC → a VPC
- Lambda → a Lambda function
- DynamoDB → a table
- IAM → a role/user/policy

`Service = category`

`Resource = actual thing inside that category`

eg:

If you create:

```
AWS
└── EC2
    ├── Server 1
    ├── Server 2
    └── Server 3
```

EC2 is the service.

Each server is an EC2 resource.

## Resources are created inside AWS services

A typical backend might look like:

```
AWS Account
│
├── VPC
│   ├── Subnet
│   ├── Route Table
│   └── Security Group
│
├── EC2
│   └── Go API Server
│
├── RDS
│   └── PostgreSQL Database
│
├── S3
│   └── File Bucket
│
└── Lambda
    └── Image Processing Function
```

All of these are AWS resources.

## Resource relationships

AWS resources usually don't exist independently. eg:

```
Internet
   ↓
Load Balancer
   ↓
EC2
   ↓
RDS PostgreSQL
```

The resources are all connected.

## Resources can have identifiers

AWS has a way to uniquely identify resources.These identifiers allow AWS APIs and tools to refer to specific resources.

For eg, using AWS CLI:

```
aws ec2 describe-instances
```

AWS returns information about EC2 resources, including their IDs.

## Resource ID vs Resource Name

These are not always the same thing.

Resource name

Human-friendly:

```
production-api

```

Resource ID

AWS-generated identifier:

```
i-0abc123456789
```

Eg:

```
EC2 Instance

Name:       production-api
Instance ID: i-0abc123456789
```

The ID is generally the more reliable unique identifier.

## Resource scope

Resources can have different scopes.

### Region-specific

eg:

```
ap-south-1
   └── EC2 instance
```

eg:

```
us-east-1
   └── EC2 instance
```

These are different resources in different Regions.Changing the AWS Console Region can therefore make resources appear to "disappear" when they're actually in another Region.

### Global resources

Some AWS resources/services aren't tied to one specific Region in the same way.

EG: IAM, Route 53, CloudFront

Always check the specific service documentation because resource scope and behavior can vary by service.

## Resource lifecycle

An AWS resource generally goes through:

```
Create
  ↓
Configure
  ↓
Use
  ↓
Modify
  ↓
Delete
```

Imp:
`Deleting a resource can also delete data or incur consequences depending on the service.`

```
| DNS                     | Route 53 hosted zone |
| Private network         | VPC                  |
| Serverless API function | Lambda function      |
| Container workload      | ECS service/task     |

```
