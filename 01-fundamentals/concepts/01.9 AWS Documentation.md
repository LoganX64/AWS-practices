# AWS Documentation

AWS has a very large documentation ecosystem. Goal is not to memorize the documentation ->

`you need to become good at finding the correct documentation and understanding it.`

## The most important AWS documentation site

Official AWS documentation:

https://docs.aws.amazon.com/

From there you can find documentation for almost every AWS service.

## Three types of AWS documentation you should know

A. User Guide

Usually explains:

`How the service works and how to use it.`

B. API Reference
Explains the actual AWS APIs.

C. CLI Reference
Explains AWS CLI commands.
The CLI reference tells you:

- command syntax
- options
- parameters
- examples

## Documentation version/date matters

AWS documentation can change. So when learning AWS, prefer current official documentation.

This is particularly important for:

- IAM
- security
- pricing
- service limits
- APIs
- SDKs
- authentication

## Read the "Prerequisites"

Many AWS tutorials have prerequisites.
eg:

```
Before you begin
    ↓
AWS account
    ↓
IAM permissions
    ↓
CLI configured
    ↓
Region selected
```

Don't skip these sections.

A tutorial may fail simply because a prerequisite wasn't configured.

## Pay attention to permissions

AWS documentation often contains commands that require specific permissions.

For example:

```
s3:PutObject
s3:GetObject
s3:DeleteObject
```

If your command fails with:

```
AccessDenied
```

This connects directly to what you learned in: 01.7 — ARNs

## Pay attention to quotas and limits

AWS services have limits.For example, a service may have limits involving:

- API requests
- resource counts
- storage
- payload size
- concurrency
- throughput

its under documentation sections.

## Documentation is part of debugging

Suppose your Go application gets:

```
AccessDenied
```

our debugging process can be:

```
Error
 ↓
Identify AWS service
 ↓
Search official docs
 ↓
Check API requirements
 ↓
Check IAM permissions
 ↓
Check resource ARN
 ↓
Check Region
 ↓
Test again
```

## Documentation reading workflow

Use this workflow when learning a new AWS service:

```
1. What is it?
       ↓
2. What problem does it solve?
       ↓
3. Core concepts
       ↓
4. Architecture
       ↓
5. Getting started
       ↓
6. Pricing
       ↓
7. Security / IAM
       ↓
8. Limits / quotas
       ↓
9. API / CLI / SDK
       ↓
10. Best practices

```

You don't always need all ten steps.
