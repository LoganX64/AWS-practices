# Managed vs Unmanaged Services

This concept is about how much infrastructure we are responsible for.

`Unmanaged → we operate more.`

`Managed → AWS operates more for us.`

## Unmanaged / Self-Managed

With a self-managed service, we are responsible for much more of the infrastructure and software.

We may be responsible for:

- OS updates
- PostgreSQL installation
- PostgreSQL updates
- Configuration
- Backups
- Monitoring
- Security configuration
- Scaling
- Failure recovery

AWS still manages the underlying physical infrastructure, but we manage the software environment we installed.

## Managed Service

With a managed service, AWS handles more of the infrastructure and operational work.

AWS manages much of the underlying infrastructure and database service operations.

we still have responsibilities such as:

- Database configuration
- Users and permissions
- our data
- Schema
- Queries
- Application-side

## Why Use Managed Services?

Managed services can reduce operational work.

We still need to understand databases, security, backups, monitoring, and availability. AWS simply takes over more of the infrastructure work.
