# AWS ARNs

we need a more precise way to identify AWS resources. That's where ARN comes in.

## What is an ARN?

ARN = Amazon Resource Name

An ARN is a standardized identifier used to uniquely identify AWS resources.

Think of it like an absolute address for an AWS resource.

AWS can identify a resource using something like:

```
 arn:aws:lambda:ap-south-1:123456789012:function:process-image
```

## ARN structure

A typical ARN looks like:

```
arn:partition:service:region:account-id:resource
```

eg:

```
arn:aws:lambda:ap-south-1:123456789012:function:process-image
```

break down:

```
arn
│
├── aws
│   └── partition
│
├── lambda
│   └── service
│
├── ap-south-1
│   └── region
│
├── 123456789012
│   └── AWS account ID
│
└── function:process-image
    └── resource
```

## ARN components

```
| Part       | Example                  | Meaning                   |
| ---------- | ------------------------ | ------------------------- |
| `arn`      | `arn`                    | Identifies this as an ARN |
| partition  | `aws`                    | AWS partition             |
| service    | `lambda`                 | AWS service               |
| region     | `ap-south-1`             | AWS Region                |
| account-id | `123456789012`           | AWS account               |
| resource   | `function:process-image` | Specific resource         |

```

```
arn:aws:lambda:ap-south-1:123456789012:function:process-image
```

means roughly:

`The process-image Lambda function belonging to account 123456789012 in ap-south-1.`

## Different services have different ARN formats

ARNs are standardized, but the resource portion differs by service.

S3

```
arn:aws:s3:::my-production-bucket
```

There is no Region in this ARN.

Lambda

```
arn:aws:lambda:ap-south-1:123456789012:function:process-image
```

IAM Role

```
arn:aws:iam::123456789012:role/backend-role
```

IAM is a global service, so there is no Region:

```
arn:aws:iam::ACCOUNT_ID:role/ROLE_NAME
```

## Why are ARNs important?

Biggest reasons is IAM permissions.
Suppose our Go backend needs permission to upload files to a specific S3 bucket.
Instead this application to access S3. You can specify the exact resource:

```
arn:aws:s3:::my-production-bucket
```

Conceptually:

```
IAM Policy
    │
    ├── Effect: Allow
    ├── Action: s3:GetObject
    └── Resource:
        arn:aws:s3:::my-production-bucket/*
```

This allows you to define which resources a principal can access.

## ARN + IAM = very important

```
Principal
    ↓
IAM Policy
    ↓
Action
    ↓
Resource ARN
```

`The application can perform a specific S3 action on a specific resource.` This is a fundamental AWS security concept.

## ARN wildcards

we can use wildcards in IAM policies where supported.
eg:
`arn:aws:s3:::my-app-files/*`

means objects inside - `my-app-files`.
The `*` represents matching object paths.

Important:every ARN pattern does not works identically, wildcard behavior depends on the policy element and service.

## ARN vs Resource ID

Both are different concept.

Resource ID

```
i-0abc123456789
```

Identifies an EC2 instance.

ARN

```
arn:aws:ec2:ap-south-1:123456789012:instance/i-0abc123456789
```

Provides a standardized, fully qualified AWS resource name.

`Resource ID
    ->
Short identifier`

`ARN
    ->
Full AWS resource address`
