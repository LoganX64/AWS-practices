# AWS Services

The goal of this section is not to memorize hundreds of AWS services.

## Compute

Compute services provide the resources needed to run applications and code.

```
                    Compute
                       │
       ┌───────────────┼───────────────┐
       ▼               ▼               ▼
      EC2            ECS              EKS
       │               │               │
   Virtual        Containers      Kubernetes
   machines
                       │
                       ▼
                    Lambda
                       │
                    Functions
```

### EC2 — Elastic Compute Cloud

EC2 = Virtual Server

we rent a virtual machine from AWS.
we have a lot of control over the server.

we can choose:

- CPU
- RAM
- Storage
- Operating system
- Networking
- Security configuration
- Use EC2 when:

we want control over the server and operating environment.

`EC2 = "Give me a virtual machine."`

### Lambda

Lambda = Run code without managing servers directly.

we upload a function, and AWS runs it when triggered, but we don't manage an EC2 server ourself.

Use Lambda when:

- Event-driven processing
- Small APIs/functions
- Background tasks
- Scheduled jobs
- File processing

`Lambda = "Run my function when needed."`

### ECS — Elastic Container Service

ECS = AWS service for running containers.
AWS manages the container orchestration layer, while we configure how our containers run.

ECS can run containers using infrastructure such as EC2 or AWS Fargate.

Use ECS when:

we have Dockerized applications and want AWS-managed container orchestration without adopting Kubernetes.

`ECS = "Run my Docker containers on AWS."`

### EKS — Elastic Kubernetes Service

EKS = Managed Kubernetes on AWS.

```
             EKS
              │
       Kubernetes cluster
        /       |       \
       ▼        ▼        ▼
   Container Container Container
```

AWS manages the Kubernetes control plane, while we manage/configure Kubernetes workloads and other parts of the environment depending on the architecture.

Use EKS when:

- we need Kubernetes
- Our organization uses Kubernetes
- we need Kubernetes ecosystem/tools
- we want Kubernetes portability

`EKS = "Give me Kubernetes on AWS."`

## Storage

Storage services are used to store files, disks, and shared file systems.

```
                    Storage
                       │
           ┌───────────┼───────────┐
           ▼           ▼           ▼
          S3          EBS         EFS
        Objects      Disk        File system
```

### S3 — Simple Storage Service

S3 = Object storage.

Used for things such as:

- Images
- Videos
- PDFs
- Backups
- Logs
- Static website files
- Application uploads

S3 stores objects inside buckets.

Use S3 when:
we need to store files/objects rather than a normal filesystem attached to a server.

`S3 = "Store my files/objects."`

### EBS — Elastic Block Store

EBS = Persistent block storage for EC2.

Its like a virtual hard disk.

An EC2 instance can use EBS volumes for:

- Operating system
- Application files
- Databases
- Other disk-based workloads

`EBS = "Give my EC2 a virtual disk."`

### EFS — Elastic File System

EFS = Managed shared file system.

Multiple compute resources can access the same filesystem. Useful when multiple servers need access to shared files.
`EFS = "Give multiple servers a shared filesystem."`

## Database

These services provide different approaches to storing application data.

````
                    Database
                       │
       ┌───────────────┼────────────────┐
       ▼               ▼                ▼
      RDS            Aurora         DynamoDB
   Relational      Relational       NoSQL
                       │
                       ▼
                  ElastiCache
                     Cache
                     ```
````

### RDS — Relational Database Service

RDS = Managed relational databases.

Instead of installing PostgreSQL ourself on EC2, WS handles much of the underlying database infrastructure and operational work.

RDS supports engines such as:

- PostgreSQL
- MySQL
- MariaDB
- Oracle
- SQL Server

Use RDS when:

Our application needs a traditional relational database.

` RDS = "Give me a managed relational database."`

### Aurora

Amazon Aurora = AWS relational database engine compatible with PostgreSQL and MySQL.

Designed by AWS for cloud-oriented relational database workloads.

Aurora is part of the RDS family of managed database offerings, but it is a distinct database engine.

`Aurora = "AWS's cloud-optimized relational database engine."`

### DynamoDB

DynamoDB = Managed NoSQL database.

It is a key-value/document database.

eg:

```
User ID → User data

1001 → {
         name: "Jitin",
         age: 25
       }
```

It is designed for very high-scale, low-latency workloads.

Use DynamoDB when:

Our application's data model fits a NoSQL/key-value/document approach.

`DynamoDB = "Managed NoSQL database."`

### ElastiCache

ElastiCache = Managed in-memory caching.

It supports technologies such as:

- Redis/Valkey-compatible caching depending on AWS offering/configuration
- Memcached

`ElastiCache = "Keep frequently used data in memory for faster access."`

## Networking

Networking services connect our applications and users.

```
                    Networking
                         │
       ┌─────────────────┼─────────────────┐
       ▼                 ▼                 ▼
      VPC             Route 53          CloudFront
    Network              DNS               CDN
                         │
                         ▼
                        ELB
                 Load Balancing
```

### VPC — Virtual Private Cloud

VPC = Our logically isolated network in AWS.

we define things such as:

- IP ranges
- Subnets
- Routing
- Security controls
- Internet connectivity

eg :

```
                 VPC
                  │
        ┌─────────┴─────────┐
        │                   │
   Public Subnet       Private Subnet
        │                   │
     Load Balancer       Go API
                            │
                         Database

```

`VPC = "My private network inside AWS."`

### Route 53

Route 53 = AWS DNS service.

DNS translates domain names into destinations.

`Route 53 = "Manage DNS and domain routing."`

### CloudFront

CloudFront = AWS Content Delivery Network (CDN).

It caches and delivers content from AWS edge locations closer to users.

Useful for:Images,Videos,JavaScript,CSS,Static websites, Some API delivery patterns

`CloudFront = "Deliver content closer to users."`

### ELB — Elastic Load Balancing

ELB distributes incoming traffic across multiple targets.

eg:

```
              Users
                │
                ▼
         Load Balancer
          /          \
         ▼            ▼
      Go API        Go API
      Server 1      Server 2
```

Instead of sending every request to one server, the load balancer distributes traffic.

AWS provides several load-balancing types, including:

- Application Load Balancer (ALB)
- Network Load Balancer (NLB)
- Gateway Load Balancer (GWLB)

## Security

These services help control access, protect data, store secrets, and protect applications.

```
                    Security
                       │
       ┌───────────────┼───────────────┐
       ▼               ▼               ▼
      IAM             KMS       Secrets Manager
   Permissions       Encryption      Secrets
                       │
                       ▼
                      WAF
                 Web protection
```

### IAM — Identity and Access Management

IAM controls who can access AWS resources and what they can do.

IAM involves:

- Users
- Roles
- Policies
- Permissions

`IAM = "Who can do what?"`

### KMS — Key Management Service

KMS = Managed encryption key service.

It helps us create and control cryptographic keys used to protect data. KMS can be integrated with many AWS services.

`KMS = "Manage encryption keys."`

### Secrets Manager

Secrets Manager = Secure storage for secrets.

`Secrets Manager = "Store sensitive credentials securely."`

### WAF — Web Application Firewall

AWS WAF helps protect web applications from common web attacks and unwanted traffic.

It can inspect HTTP/HTTPS requests and apply rules.It can be associated with supported AWS resources such as CloudFront and Application Load Balancer.

`WAF = "Filter and protect web traffic."`

## Monitoring

Monitoring tells us what is happening in our AWS environment.

## CloudWatch

CloudWatch = Monitoring and observability service.

It can work with:

- Metrics
- Logs
- Alarms
- Dashboards
- Events

\*Memory monitoring for EC2 generally requires additional configuration/agent-based collection rather than being an automatic basic EC2 metric.

## CloudTrail

CloudTrail records AWS API activity and account actions.

we can use it to investigate things such as:

- Who performed an action?
- What API call occurred?
- When did it happen?
- Which AWS resource was affected?.

CloudWatch vs CloudTrail

CloudWatch -> "What is happening to my workload?"

CloudTrail -> "Who did what in my AWS account/API?"
